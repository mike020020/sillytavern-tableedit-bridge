# 正文 `<tableEdit>` 状态块填表工具包（sillytavern-tableedit-bridge）

把「正文里顺手写一个 JSON 状态块 → 卡内脚本按 DDL 校验后写进 shujuku 表格」这套做法打包出来，
**不需要每轮再调用一次填表 AI**，表格更新确定、可控、可校验。

## 包里有什么

| 文件 | 用途 |
| --- | --- |
| `tableEdit-bridge.js` | 状态桥脚本（可直接贴进酒馆助手 / JS-Slash-Runner）。表名列名是占位示例，改 `SCHEMA` 即可用 |
| `worldbook-协议条目模板.yaml` | 世界书协议条目模板（YAML 写作版，方便阅读与改） |
| `worldbook-协议条目模板.json` | 同一份协议的 SillyTavern 导入格式（世界书 → 导入） |

工作方式一句话：**协议条目**告诉模型「允许写哪些表、哪些列、什么格式」；**桥脚本**负责把这些声明变成校验与写库。

## 三步装好

1. **贴脚本**：打开 `tableEdit-bridge.js` 整段复制，贴进酒馆助手（JS-Slash-Runner）新建脚本，脚本名建议「结构化状态同步桥」。
   - 脚本顶部的 `SCHEMA` 是表/列白名单，把 `demo_state` / `demo_npc_state` / `demo_npc_profile` 换成**你自己卡模板里的物理表名**，
     把 `example_*` 换成对应表的 DDL 列名（枚举、范围、正则、长度、默认值都写在列的声明里）。
2. **加协议条目**：把你改好的表/列规则写进世界书（两种方式任选）
   - 方式 A：世界书面板 → 导入 → 选 `worldbook-协议条目模板.json`；
   - 方式 B：新建条目，把 `worldbook-协议条目模板.yaml` 的 `content` 整段粘进去（推荐，方便按自己的表改）。
   - 建议设 **constant（常开）**，位置 `Before Char`；关键词留空不影响常开条目。
   - 协议条目里的表名/列名要**与脚本 SCHEMA 完全一致**。
3. **关掉这几张表的自动填表**：在数据库插件模板里把走状态块的表的 `updateConfig.updateFrequency` 设成 `0`
   （`-1` 是「跟随全局」，不等于关闭），然后回包 / 重新导入模板。

装好后的每轮：正文末尾带一个状态块 → 桥自动校验并写库；写不进去会在提示里说明原因。

## 自测（30 秒）

在任意聊天里手打一条（表名换成你自己的）：

```text
<tableEdit>
{"updates":[{"table":"demo_state","where":{"row_id":1},"set":{"example_time":"2026-01-01 12:00"}}]}
</tableEdit>
```

点脚本按钮「同步最后一条状态」，应提示「已写入 N 项」，表格对应单元格变化；再点一次应提示「这条状态已经同步过」。

## 与数据库插件自动填表共存

两者不必二选一：**只把走状态块的表关掉自动填表**，其余表继续交给插件（插件填表能在正文漏写细节时补一手）。
注意插件在填表期间会**拒绝外部写入**（报 `AI 填表正在进行中，已拒绝外部表格写入`），而且此时写入会让它的基线失效、
整轮填表失败。桥的处理是：

- 注册插件的「填表开始」回调（它没有「填表结束」回调），并把「填表进行中」状态挂在**顶层窗口**上全局共享；
- 写入前过闸门：填表停止按钮不在 DOM + 距收到回复 ≥45 秒 + 距最近一次表格写入 ≥20 秒；
- 用「试写」判断填表是否结束（被拒＝还在填表），退避 30s → 45s → 60s，超过 10 分钟转 5 分钟慢等，**不放弃**；
- 填表标记安静超过 3 分钟视为过期，允许试写一次；
- 你确认填表早已结束时，点按钮会弹确认框，确认即**越权同步**（等价入口 `window.TableEditBridge.forceSync()`）。

代价：状态块同步会晚于回复（正常约 1 分钟内，遇到填表更久），换来的是不会打断填表、不浪费填表调用。

## 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 提示「没有 tableEdit 状态块」 | 模型没输出，或输出在了被隐藏的思维链里；看提示里的「读到 N 条消息 / 来源 / 末条开头」定位 |
| 提示「JSON 解析失败」 | 状态块 JSON 非法；桥只取**最后一对** `<tableEdit>` 标签，正文里其它地方出现该字样不影响 |
| 提示「表不允许或表名不符合 DDL」 | 协议/脚本里的表名写成中文名或带 `sheet_` 前缀；要用物理表名 |
| 提示「不允许写入列」/「没有可写列」 | 列名不在白名单；用 DDL 列名，或把该列加进协议与脚本 SCHEMA |
| 提示「格式必须是…」「只能是…」 | 与 DDL 约束冲突；这类错误整块拒绝，不会写半条 |
| 提示「新建行缺少必填列」 | 新增行缺无默认值的列；补上，或先 updates 再建档 |
| 提示「读不到当前表格内容」 | 目标表没导入或读不到；这条保护用来防止误判成新行、撞 UNIQUE |
| 状态一直没同步 | 可能仍认为填表在进行：等一轮，或点按钮走**越权同步** |

## 边界

- 脚本按 shujuku（SP·数据库）9.x 的公开 API 写：`exportTableAsJson` / `updateRow` / `updateCell` / `insertRow` /
  `getTableLockState` / `registerTableFillStartCallback` / `registerTableUpdateCallback` / `refreshDataAndWorldbook`。
  上游大版本升级后请重新确认这些接口（SQL 分组 API 是 runtime-gated，取不到时应回退到 `exportTableAsJson`）。
- 工具包只提供「桥 + 协议模板」，**不含任何角色卡内容**；表名、列名、枚举都要按你自己的卡改。
