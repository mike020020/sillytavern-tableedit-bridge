# 状态栏跨表取数（shujuku 表格 → 前端 UI）

> 本文讲**前端怎么从 shujuku（SP·数据库）表格里取数**，重点是**跨表**：一张表拿不到完整信息时，如何用外键、多行聚合或只读 SQL 把多张表拼成一份快照，再交给渲染层。
>
> 配套文档：`建表指导/TableEdit状态块与状态桥实现.md`（这些表是**怎么写进去的**）。
> 本文所有表名、列名、字段、路径都是占位示例（`demo_*` / `example_*` / `<卡项目>`），照做时换成你自己模板里的物理表名与 DDL 列名。

---

## 零、先想清楚三件事

1. **谁是数据源**：状态栏只读表格，不写表格（写入走 `<tableEdit>` 状态桥，见配套文档）。
2. **谁是渲染层**：渲染只读「快照对象」，不直接调数据库 API——这样换主题、换布局都不用动取数逻辑。
3. **一次取数、一次渲染**：每次刷新只调一次 `exportTableAsJson()`，把结果在内存里复用；避免「每个字段都去问一次 API」。

```text
 shujuku 表格（多张） ──exportTableAsJson / 只读 SQL──▶ getDatabaseSnapshot() ──快照对象──▶ 渲染层
        ▲                                                        │
        └──────── registerTableUpdateCallback / 消息事件 ────────┘（触发重新取数 + 重渲染）
```

## 一、拿到 API

状态栏脚本通常跑在楼层 iframe 里，不同宿主下 API 可能挂在 `window`、`parent` 或 `top` 上——三处都要试：

```js
function getTableApi() {
  const candidates = [
    window.AutoCardUpdaterAPI,
    window.parent && window.parent !== window ? window.parent.AutoCardUpdaterAPI : null,
    window.top && window.top !== window ? window.top.AutoCardUpdaterAPI : null
  ];
  return candidates.find((api) => api && typeof api.exportTableAsJson === 'function') || null;
}
```

拿不到 API 时**不要抛错**：直接返回空快照并让界面显示「数据库未就绪」，等下一次刷新再试（切聊天、重载脚本期间 API 会短暂不可用）。

## 二、读表三步：找表 → 找列 → 找行

### 2.1 找表：导出结构有两种形态

`exportTableAsJson()` 返回的是**当前聊天里所有表的副本**，典型结构：

```js
{
  sheet_demo_state:        { name: '示例状态表',   content: [ ['row_id', '当前位置'], [1, '某地点'] ] },
  sheet_demo_profile:      { name: '示例档案表',   content: [ ['name', '外貌'], ['NPC甲', '短发'] ] },
  '示例NPC状态表':         [ ['npc_name', 'example_score'], ['NPC甲', 15] ]      // 少数宿主直接给二维数组
}
```

所以要写一个「宽松找表」函数，按**uid（`sheet_<物理表名>`）** 和 **显示名**都认：

```js
const findSheet = (all, tableKey, displayName) => {
  const byUid = all[`sheet_${tableKey}`];
  if (byUid && Array.isArray(byUid.content)) return byUid.content;
  if (Array.isArray(byUid)) return byUid;
  for (const key in all) {
    const sheet = all[key];
    if (sheet && sheet.name === displayName && Array.isArray(sheet.content)) return sheet.content;
  }
  if (Array.isArray(all[displayName])) return all[displayName];
  if (all[displayName] && Array.isArray(all[displayName].content)) return all[displayName].content;
  return null;                      // 找不到就返回 null，调用方给兜底值
};
```

### 2.2 找列：表头可能是显示名，也可能是 DDL 列名

同一个表在不同运行模式下表头不一样：

- **native 模式**（插件原生存储）：表头常常是**显示名**（例如「当前位置」「示例时间」）；
- **SQLite 模式**：表头常常是**DDL 列名**（例如 `current_location`、`example_time`）。

取数时必须**两种都认**，否则换个模式就整列读空：

```js
const pickIndex = (headers, names) => {
  for (const name of names) {
    const index = headers.indexOf(name);
    if (index >= 0) return index;
  }
  return -1;
};

// 语义上同一个字段的所有别名都列进来：DDL 名优先，再显示名
const COL = {
  location: ['current_location', '当前位置'],
  time:     ['example_time', '示例时间'],
  score:    ['example_score', '示例数值'],
  tag:      ['example_tag', '示例标签']
};
```

### 2.3 找行：单行 / 按唯一列 / 按外键

```js
const cellAt = (rows, rowIndex, names) => {
  if (!rows || !rows[rowIndex]) return null;
  const index = pickIndex(rows[0] || [], names);
  return index >= 0 ? rows[rowIndex][index] : null;
};

// 单行表：约定 row_id=1
const singleRow = (rows) => {
  const index = pickIndex(rows && rows[0] || [], ['row_id']);
  if (index < 0) return 1;                                   // 没有 row_id 列就按第 1 行
  for (let row = 1; row < rows.length; row += 1) {
    if (String(rows[row][index]) === '1') return row;
  }
  return 1;
};

// 按唯一列找行（拿不到返回 -1）
const findRow = (rows, names, value) => {
  if (!rows) return -1;
  const index = pickIndex(rows[0] || [], names);
  if (index < 0) return -1;
  for (let row = 1; row < rows.length; row += 1) {
    const current = rows[row] ? rows[row][index] : null;
    if (current != null && String(current) === String(value)) return row;
  }
  return -1;
};
```

## 三、跨表取数的五种手法

下面按「从简单到复杂」排列，实际取数通常是几种混用。

### 3.1 同表多列：一行取多个字段

最基础：定位到行，然后按列名取多个值。

```js
const main = findSheet(all, 'demo_state', '示例状态表');
const row = singleRow(main);
const snapshotEnvironment = {
  当前时间: cellAt(main, row, COL.time) || '未知',
  当前位置: cellAt(main, row, COL.location) || '未知'
};
```

### 3.2 外键跨表：用 A 表的键去 B 表找行

典型场景：**主表只有一行（主角/全局），明细在另一张表里**，靠外键列（如 `protagonist_row_id`、`owner_id`）关联。

```js
const main = findSheet(all, 'demo_state', '示例状态表');
const profile = findSheet(all, 'demo_profile', '示例档案表');

const mainRow = singleRow(main);
const mainRowId = cellAt(main, mainRow, ['row_id']) || 1;

// B 表用外键指向 A 表的行；找不到外键列时退化成「单行表」
const profileRow = findRow(profile, ['protagonist_row_id', '主角行号'], mainRowId);
const profileIndex = pickIndex(profile && profile[0] || [], COL.college) >= 0
  ? profileRow
  : singleRow(profile);                       // 兼容没有外键列的老表结构

const snapshotPlayer = {
  所属: cellAt(profile, profileIndex, COL.college) || '未登记'
};
```

要点：

- **外键列名也要写别名**（`protagonist_row_id` / `主角行号`），否则旧存档读不到；
- 找不到对应行时给「未登记」这类兜底文案，而不是 `undefined`；
- 单行表之间的关联也可以简化成「两边都取 `row_id=1`」，但**不要把这种假设写死在多行表上**。

### 3.3 多行聚合：一张表 → 字典 / 数组

列表类界面（联系人、任务、物品）几乎都是这个模式：把多行聚合成**以业务主键为 key 的字典**，渲染层直接遍历。

```js
const relation = findSheet(all, 'demo_npc_state', '示例NPC状态表');
const relationMap = {};
if (relation) {
  const nameIndex = pickIndex(relation[0] || [], ['npc_name', 'NPC姓名']);
  const scoreIndex = pickIndex(relation[0] || [], COL.score);
  const tagIndex = pickIndex(relation[0] || [], COL.tag);
  if (nameIndex >= 0) {
    for (let row = 1; row < relation.length; row += 1) {
      const cells = relation[row] || [];
      const name = cells[nameIndex];
      if (name == null || String(name).trim() === '') continue;
      relationMap[String(name).trim()] = {
        数值: scoreIndex >= 0 ? cells[scoreIndex] : '',
        标签: tagIndex >= 0 ? cells[tagIndex] : ''
      };
    }
  }
}
```

渲染层就能写「有值显示值、没值不占行」的逻辑，而不用关心表格上有没有这一行。

### 3.4 一对多拼装：把 B 表字段挂到 A 表每一行

需要「列表里每行都要带上另一张表的补充信息」时（例如列表项 + 该对象的档案摘要），**先在快照里拼好**，不要放到渲染循环里去查表：

```js
const list = findSheet(all, 'demo_npc_state', '示例NPC状态表');
const profiles = findSheet(all, 'demo_npc_profile', '示例NPC档案表');
const items = [];
if (list) {
  const nameIndex = pickIndex(list[0] || [], ['npc_name', 'NPC姓名']);
  for (let row = 1; row < list.length; row += 1) {
    const name = String((list[row] || [])[nameIndex] || '').trim();
    if (!name) continue;
    const profileRow = findRow(profiles, ['name', '姓名'], name);        // ← 跨表按名字取
    items.push({
      名称: name,
      数值: cellAt(list, row, COL.score),
      简介: cellAt(profiles, profileRow, ['brief_intro', '人物简介']) || ''
    });
  }
}
```

> 复杂度提示：这是在内存里做 N 次线性查找。几十行没问题；几百行以上建议改用下面的只读 SQL。

### 3.5 只读 SQL：JOIN / 聚合 / 子查询

SQLite runtime 就绪时，shujuku 会暴露只读 SQL 接口，可以直接把跨表逻辑交给数据库：

```js
const query = (sql, params = []) => {
  try {
    return api.executeSqlQuery?.(sql, params, { limit: 200 })
        || api.querySql?.(sql, params, { limit: 200 })
        || null;
  } catch (error) {
    return null;
  }
};

// 跨表 JOIN：列表 + 档案摘要
const joined = query(
  'SELECT s.npc_name, s.example_score, p.brief_intro ' +
  'FROM demo_npc_state s LEFT JOIN demo_npc_profile p ON p.name = s.npc_name ' +
  'ORDER BY s.example_score DESC'
);

// 聚合：算个数 / 求和
const total = query('SELECT COUNT(*) AS 总数, SUM(example_score) AS 合计 FROM demo_npc_state');
```

**必须写回退分支**：只读 SQL 接口是 **runtime-gated** 的——没有 SQLite runtime 的宿主（以及本地 mock）里它们返回 `null`。所以正确姿势是「**SQL 优先，失败回退 `exportTableAsJson` 聚合**」：

```js
const relationMap = {};
const sqlRows = (query('SELECT npc_name, example_score, example_tag FROM demo_npc_state') || {}).rows;
if (Array.isArray(sqlRows) && sqlRows.length) {
  for (const row of sqlRows) {
    if (!row || !row.npc_name) continue;
    relationMap[row.npc_name] = { 数值: row.example_score, 标签: row.example_tag };
  }
} else {
  // ↑ 拿不到 SQL 就退回 3.3 的表格聚合写法
}
```

## 四、组装快照对象

取数函数的输出应当是一个**纯数据对象**，命名按界面语义分组，渲染层只认这个结构：

```js
function getDatabaseSnapshot() {
  const api = getTableApi();
  if (!api) return null;                       // 未就绪：界面显示占位，等下轮刷新
  const all = api.exportTableAsJson() || {};   // ★ 全流程只调这一次

  const mainRows    = findSheet(all, 'demo_state', '示例状态表');
  const profileRows = findSheet(all, 'demo_profile', '示例档案表');
  const npcRows     = findSheet(all, 'demo_npc_state', '示例NPC状态表');

  const mainRow = singleRow(mainRows);
  return {
    世界环境: {
      当前时间: cellAt(mainRows, mainRow, COL.time) || '未知',
      当前位置: cellAt(mainRows, mainRow, COL.location) || '未知'
    },
    玩家角色: {
      基础信息: {
        姓名: cellAt(profileRows, singleRow(profileRows), ['name', '姓名']) || '同学'
      },
      // 跨表：多行聚合
      人际关系: buildRelationMap(npcRows)
    },
    列表: buildItemList(npcRows, profileRows)   // 跨表：一对多拼装
  };
}
```

渲染层只做两件事：**读快照**、**产出 HTML**：

```js
const render = () => {
  const snapshot = getDatabaseSnapshot() || {};
  content.html(renderModule('home')(snapshot));
};
```

## 五、刷新与重渲染

取数结果要**跟着表格变化走**，同时别把界面刷爆：

```js
// 1) 表格更新回调（写入完成、别的脚本改表都会触发）
const api = getTableApi();
if (api && typeof api.registerTableUpdateCallback === 'function') api.registerTableUpdateCallback(debouncedRender);

// 2) 消息事件兜底（新回复里可能有新状态块）
if (typeof eventOn === 'function' && window.tavern_events) {
  eventOn(tavern_events.MESSAGE_RECEIVED, debouncedRender);
  eventOn(tavern_events.MESSAGE_RENDERED, debouncedRender);
}

// 3) 首次加载时轮询几次：脚本常早于数据就绪执行
let tries = 0;
const timer = setInterval(() => { render(); if (++tries > 6) clearInterval(timer); }, 500);

// 4) 去抖：同一波更新只渲染一次
let renderTimer = null;
function debouncedRender() {
  if (renderTimer) clearTimeout(renderTimer);
  renderTimer = setTimeout(() => { renderTimer = null; render(); }, 300);
}
```

要点：

- **去抖**（300ms 左右）比「每个回调都渲染」稳定得多；
- 首次轮询只跑几次就停，别做成常驻定时器；
- 如果界面元素是**动态插入**的，渲染后要重新绑定事件，或统一用**事件委托**（`container.on('click', '.child', handler)`）。

## 六、性能与稳定性

| 事项 | 做法 |
| --- | --- |
| API 调用次数 | 一次刷新只调一次 `exportTableAsJson()`；SQL 同理，每次刷新最多几次 |
| SQL 结果量 | 一律带 `{ limit: ... }`，列表类查询在 SQL 里排序/过滤，别拉全表到前端再筛 |
| 表规模 | 多行表聚合是 O(N) 内存操作；N 上百就改用 SQL（见 3.5） |
| 空表 / 缺列 | 每个取值都带兜底（`|| '未知'`、`|| '0'`）；表或列不存在时返回 `null` 让上层决定文案 |
| 数值字段 | 表格里的值可能是字符串：需要算术就用 `Number(...)`/`parseInt(...)`，并处理 `NaN` |
| 数值显示 | 结构变化（列顺序调整）不应导致读错列——**永远按列名取，不写死下标** |
| 长文本 | 快照里保留原文，截断交给渲染层（CSS/`slice`），方便随时调整展示长度 |

## 七、常见坑（逐条踩过）

1. **表名/列名写死不写别名**：换成 SQLite 模式（表头变 DDL 列名）或改名后就整列读空。→ 一律用 2.1/2.2 的宽松查找。
2. **只认 `sheet_xxx` 或只认显示名**：不同宿主导出结构不同。→ 两种都查，再兜「表名 → 二维数组」。
3. **把 `exportTableAsJson()` 的返回值当成可写对象**：它是副本，改了不会写回表格。→ 写表用 `updateRow`/`updateCell`/`insertRow`（见配套文档）。
4. **依赖只读 SQL 一定可用**：它是 runtime-gated，没有 SQLite runtime（或本地 mock）时返回 `null`。→ 必须有表格回退分支。
5. **单行表的假设扩散到多行表**：把「取第 1 行」用在按名字定位的表上，会永远只看第一个 NPC。→ 单行表用 `row_id=1`，多行表用 `findRow`。
6. **外键列名不带别名**：`protagonist_row_id` 与「主角行号」是同一列，旧存档可能只有中文表头。→ 别名数组里都写上。
7. **在渲染循环里查表**：一行一次 `findSheet`，表大了会明显卡。→ 先拼快照（3.4），或改 SQL（3.5）。
8. **没有兜底值**：缺列/空行时直接渲染 `undefined`。→ 统一 `|| '未知'`，并处理空表文案（「通讯录暂无联系人」这种）。
9. **每次事件都全量渲染**：状态块写入 + 表格更新 + 消息渲染会在同一秒内触发多次。→ 去抖 300ms。
10. **手改卡内 JSON 资产**：状态栏脚本/取数块通常由**生成脚本**产出，手改会在下次运行时被覆盖。→ 改生成脚本再重跑（见第八节）。

## 八、怎么改：正确的维护姿势

状态栏脚本（酒馆助手脚本）里的取数块建议**由脚本生成**，而不是每次手改 JSON 字符串：

```text
tools/cards/<卡标识>/migrate-status-bar-columns.mjs   ← 取数逻辑写在这里（含表名/列别名/聚合/SQL）
        │  node tools/cards/<卡标识>/migrate-status-bar-columns.mjs
        ▼
projects/<卡名>/unpacked/tavern_helper/scripts/002-状态栏.json   ← 生成物：只提交、不手改
```

好处：改取数是改一段可读的 JS，重跑即可；生成物里不会残留半手写状态。

## 九、怎么验证（不必开真机）

1. **准备 mock 数据**：把要读的几张表（含**跨表关联键**）写成 `{ "seedTables": { "表名": [[表头],[数据行]] } }`；
2. **跑本地前端预览**：把状态栏脚本包成 HTML（或直接用工具链的 frontend runner）加载 mock 数据，断言渲染文本里出现了跨表取到的值；
3. **断言的写法**：别只断言「页面有输出」，要断言**具体字段**——例如「联系人行里出现态度简述」「外键关联的学籍信息出现」，这样列名/表名写错时才会失败；
4. **两种表头各测一遍**：native（中文表头）与 SQLite（DDL 列名表头）各跑一次，验证 2.2 的别名查找确实生效。

最小自测思路（伪代码）：

```text
给定：demo_state(row_id=1, example_time='2026-01-01 12:00')
      demo_profile(protagonist_row_id=1, college='示例学部')
      demo_npc_state(NPC甲, example_score=15, example_tag='初识')
期望：快照.世界环境.当前时间 == '2026-01-01 12:00'
     快照.玩家角色.所属 == '示例学部'            ← 外键跨表
     快照.玩家角色.人际关系['NPC甲'].标签 == '初识' ← 多行聚合
```

## 附：本文用到的 API

| API | 用途 | 注意 |
| --- | --- | --- |
| `exportTableAsJson()` | 一次性导出所有表的副本 | 只调一次，在内存里复用 |
| `executeSqlQuery()` / `querySql()` | 只读 SQL（JOIN / 聚合） | **runtime-gated**，取不到要回退表格 |
| `registerTableUpdateCallback()` | 表格更新时重渲染 | 配合去抖 |
| `updateRow()` / `updateCell()` / `insertRow()` | 写表（本文不涉及，见配套文档） | 写入请走状态桥，别在前端散写 |
